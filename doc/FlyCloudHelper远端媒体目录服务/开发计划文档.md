# FlyCloudHelper 远端媒体目录服务 开发计划文档

生成日期：2026-08-14

## 1. 目标

完成一套可 Docker 部署、同时支持视频、音乐、有声书并可持续增加网盘 Provider 的云端扫描、元数据和媒体目录服务。单个部署必须支持多个用户名密码账号、每个账号多个云端服务，并通过 `tenantId + serviceId + libraryId` 所有权链保证扫描、刮削、查询、进度和导出归属一致。用户名和密码都至少 4 个字符，角色首期固定为 `user` 和 `super_admin`。空数据库实例首次使用时进入 `/setup`，由部署者现场设置首个超级管理员用户名、密码和确认密码，不要求一次性初始化凭证，也不通过环境变量预置账号密码；成功后初始化入口永久关闭。APP 开启云端模式后输入云端地址，登录已有账号或创建新账号，再选择已有服务或把当前网盘连接、扫描路径和刮削配置创建为新云端服务；扫描触发只引用服务端配置，不再逐任务上送临时凭据。音乐处理参考 FlymbyServer 已有的多来源聚合、标准字段和可选 Chromaprint/AcoustID 声纹链路，但迁入 FlyCloudHelper Worker，不能形成默认在线依赖。同镜像提供 `/login` 登录入口、`/register` 普通用户注册入口、`/app` 个人控制台和 `/admin` 超级管理员后台；普通用户管理本人服务、任务与媒体目录，超级管理员管理全局用户、服务、插件、任务与系统配置。Web 前端不支持直接播放。TMDB 多 Key 池由超级管理员在系统配置页整组维护，Key 使用凭据主密钥加密入库并在保存后即时热更新；Worker 根据健康 Key 数量、单 Key配额、全局上限和可用槽位动态调整刮削并发。数据库默认使用 SQLite，也可通过环境变量切换 PostgreSQL/MySQL，并为 HarmonyOS Flymby 和 Android TV 提供统一、可版本化、媒体流不经过服务端的接入契约。

当前实施阶段只开放影视服务：创建页的 `dataType` 展示影视、音乐、有声书三个单选项，但音乐和有声书禁用；后台、Worker、能力接口和目录 facets 只接受或声明 `video`。音乐和有声书保留为后续迭代目标，不计入本阶段验收。

## 2. 技术栈和约束

| 项 | 内容 |
| --- | --- |
| 服务端技术栈 | 已确定采用 Node.js 20 + TypeScript；Web 首期使用 React、Vite、TanStack Router 和 Tailwind CSS，API/Worker 的具体框架在服务端骨架阶段冻结 |
| API | REST JSON + SSE，使用 `/api/v1` 版本前缀 |
| 任务模型 | API 与 Worker 分离；首期可同镜像不同进程角色，但不在 API 请求线程中执行长扫描 |
| 数据库 | 默认 SQLite；`FLYCLOUDHELPER_DATABASE_TYPE` 可切换 `postgres` 或 `mysql`，三种后端共享逻辑 schema 和迁移版本 |
| 账号认证 | 只支持用户名和密码，二者都至少 4 个 Unicode 字符；密码使用 Argon2id 哈希，APP 仅在系统安全存储中保存访问/刷新令牌 |
| 角色权限 | 首期固定 `user` 和 `super_admin`；公开注册只能创建 `user`，所有 `/api/v1/admin/*` 接口由服务端强制校验 `super_admin` |
| 服务凭据 | 独立长期加密存储或专用 Secret Store，不与账号密码、服务配置和媒体目录字段共表；主密钥从环境变量或 Docker Secret 读取 |
| TMDB 配置 | 管理员 `/admin/config` 整组替换多 Key；凭据主密钥加密入库；单 Key 并发默认 1，部署总并发默认上限 32 |
| TMDB 调度 | `min(全局上限, 健康 Key 数 × 单 Key 并发, Worker 可用槽位)`；最少在途 Key 分配、限流冷却、失效禁用、任务公平队列和多 Worker 共享上限 |
| 音乐元数据 | 参考 FlymbyServer 的 `AudioScrapeService`/`AudioMetadataSources`，文字检索为批量主路径，声纹仅作低置信度后备；来源通过注册表扩展 |
| Web 前端 | 与 API 同源部署；提供 `/setup`、`/login`、`/register`、`/app` 和 `/admin`。未初始化时只开放首次设置，普通用户只访问本人数据，`super_admin` 访问全局用户/服务、任务、海报墙、插件、配置状态和审计 |
| 插件管理 | 首期仅支持 `.flymby-plugin` 声明式元数据包及 schema 驱动的实例级配置，版本化存放于持久卷，不允许网页上传 Provider 或可执行代码 |
| Web 播放边界 | 管理海报墙只使用删除播放定位字段的只读 DTO，不提供播放器、播放按钮、媒体预览、临时 URL 或网盘 Headers |
| 图片存储 | 默认保存来源 URL；是否缓存原图待产品和服务端确认 |
| 客户端缓存 | 只保留短页缓存、ETag/版本、图片缓存、令牌和 `serviceId/libraryId` 绑定，不保留完整目录或云端服务凭据 |
| 归属约束 | `tenantId` 只来自认证上下文；`serviceId/libraryId` 由服务端生成；APP `clientServiceId` 只作为设备本地绑定别名 |
| 播放边界 | 客户端使用本地网盘授权解析 URL，服务端保存的扫描凭据不下发，FlyCloudHelper 不代理任何视频或音频流 |
| Provider 扩展 | 核心依赖能力接口和注册表，不使用封闭网盘枚举；适配器独立版本化 |
| 媒体类型扩展 | 通用扫描层与视频、音乐、有声书 Processor 分离，通用实体和类型扩展表并存 |
| 插件边界 | 元数据只支持受限声明式 Manifest 和宿主 HTTP；Provider 插件在受控部署阶段安装，禁止任务上送任意可执行代码 |
| 代码规则 | 函数需要注释，关键变量需要注释，逻辑优先清晰可读 |
| 日志规则 | 结构化日志，敏感字段禁止输出，中文业务 key 便于筛查 |
| 测试约束 | 按用户项目规则不编写自动化测试，以静态检查、Docker 运行检查和用户联调验收为主 |
| 当前任务 | 首期后台、Docker 文件和生产静态服务已落地；下一阶段为 Web 业务页正式接口联调、HarmonyOS/Android TV 接入及真实网盘验收 |

### 2.1 当前实施进度（2026-08-15）

1. 已建立根工作区、`web/` 和 `api/`，`npm run dev` 可同时启动 Fastify API 与 Vite Web，开发环境中由 Vite 同源代理 `/api`。
2. 已实现默认 SQLite 数据文件、WAL、外键、初始化状态、用户、密码、个人租户、会话和管理员审计基础表。
3. 已实现 `/api/v1/setup/status`、首次超级管理员初始化、普通用户注册、用户名密码登录、当前用户查询和退出登录；密码使用 Argon2id，浏览器会话使用 HttpOnly Cookie，数据库只保存会话 Token 哈希。
4. 已实现服务/媒体库归属、加密凭据和配置修订，普通用户及超级管理员均可按权限创建服务、维护连接与配置并触发扫描。
5. 已实现 WebDAV、阿里云盘、百度网盘和光鸭标准网关适配器；当前 Worker 已按 Flymby APP 主流程完成最近目录判型、电影/剧集/季集识别、默认目录排除、NFO 开关与优先级、TMDB 搜索回退、电影/电视剧详情及季集信息持久化，并以目录为单位边扫描边刮削。WebDAV 子目录读取失败会继续扫描并保护本轮旧数据不被清理，同一电影多版本、同一节目和同一集多文件按业务身份合并。APP 的扫描检查点持久化、单文件多集拆分、AI 文件名二次清洗、延迟重试队列和按单个扫描根提交 generation 仍属于后续对齐范围。
6. 已实现 TMDB 多 Key 池、声明式插件导入/配置/启停、任务快照、SSE、导出和管理审计；失败或已取消任务可创建保留原任务关联的新重试任务，普通用户和超级管理员页面均只在可重试状态开放按钮；MusicBrainz 与有声书处理暂不纳入当前开放能力。
7. 已提供 `Dockerfile`、SQLite 基础 Compose、PostgreSQL/MySQL 覆盖 Compose 和 Docker Secret 覆盖文件；当前开发机无 Docker CLI，容器和两种外部数据库尚待实际联调。
8. 已将 `/setup`、`/login`、`/register`、`/app` 和 `/admin` 接到真实认证 API，根路径会根据初始化状态、登录状态和角色跳转，普通用户不能进入超级管理员控制台。
9. 已通过 API 与 Web TypeScript 全量构建，并使用临时 SQLite 手工验证 schema 初始化、首次超级管理员、会话鉴权、管理员查询、个人概览和生产静态页面。
10. Web 服务、任务、海报墙和管理业务页仍保留演示 DTO，下一阶段逐页接入本次已完成的后台接口。

## 5. 开发步骤

### 5.1 冻结运营与技术决策

5. 确认视频和有声书元数据来源；音乐冻结 FlymbyServer 候选来源中的默认启用集合、必要字段、匹配阈值、缓存、请求限额和声纹首期范围。

7. 冻结 `/setup` 的初始化事务锁、`setup_required` 业务门禁和“先初始化再开放公网”部署流程；同时确认插件包签名要求和上传/解压资源上限。

10. 根据 OpenAPI 分别产生管理前端 TypeScript、HarmonyOS ArkTS 与 Android TV Kotlin DTO，禁止各端手写分叉契约。

## 6. 风险和处理建议

| 风险 | 表现 | 处理建议 |
| --- | --- | --- |
| 直接复制 ArkTS 扫描类 | 容器中缺少 ArkUI、Preferences 和 AppStorage | 只迁移领域规则，重建任务、存储和背景运行边界 |
| 核心写死视频字段 | 音乐、有声书只能塞入影片表，后续查询和迁移失控 | 通用 `media_item` + 类型扩展表 + `media_relation` |
| 核心写死四类网盘 | 每增加网盘都要改协议、数据库和扫描器 | 开放 Provider ID、能力协商、版本化配置和适配器注册 |
| 稳定身份不足 | 移动/重命名后误删或重复入库 | Provider 稳定 ID 优先，WebDAV 路径型单独处理 |
| 跨租户数据泄露 | 猜测 `libraryId` 后读取其他用户目录、进度或导出 | `tenantId` 只来自认证上下文，Repository、缓存、SSE、队列和对象存储全部强制租户作用域 |
| 把客户端 ID 当云端身份 | 新设备无法找到原库，或不同本地服务误共享目录 | 云端归属只使用服务端 `serviceId`；`clientServiceId` 放入独立设备绑定表，多端通过账号服务列表选择 |
| 按名称或地址归属 | 改名、换域名或同账号多路径导致误合并 | 只使用 `tenantId + serviceId` 判断服务归属，名称、URL、账号和路径均非身份字段 |
| 选择已有服务覆盖配置 | APP 当前本地路径或凭据误覆盖正在使用的云端服务 | “选择已有”只创建客户端绑定；“创建新服务”才上传当前配置，编辑云端配置必须走独立明确入口 |
| 本地与云端 Provider 不一致 | 目录可以看到但无法本地播放，或错误解析定位 | 客户端绑定时校验 Provider 类型，不一致返回 `409`；新设备未授权时只读浏览并引导本地授权 |
| 失败扫描触发删除 | 临时网络失败被当作文件删除 | 只在完整成功 generation 后对账 |
| 多端重复扫描 | 浪费限额、目录反复更新 | `requestId` 幂等 + 每媒体库单写任务 |
| 扫描中分页不稳定 | 重复/漏数据 | 查询使用游标和目录版本 |
| 用户密码泄露 | 账号和全部云端服务被接管 | Argon2id、失败响应不枚举账号、刷新令牌轮换、APP 不持久化明文密码 |
| 未初始化实例被抢占 | 首次设置不要求初始化凭证，实例若直接暴露公网可能被访客抢先创建超级管理员 | `setup_required` 时关闭其他业务接口；启动提示和部署文档要求先在受控网络完成 `/setup`，再开放反向代理或端口；初始化事务只允许成功一次 |
| 公开注册越权成为超级管理员 | 修改注册请求中的角色字段后取得全局权限 | 注册接口拒绝 `role` 并固定写入 `user`；角色变更只允许 `super_admin`，要求最近重新认证、二次确认、撤销旧会话和审计 |
| 最后一个超级管理员失效 | 无人能够进入 `/admin` 恢复系统 | 禁止降级、停用或删除最后一个有效 `super_admin`；初始化流程至少创建一个符合 4 字符规则的可登录超级管理员 |
| 服务凭据泄露 | 用户网盘被访问或数据丢失 | 与业务表分离的长期密文、每服务作用域、主密钥版本、Secret 只写不读、日志/导出禁止和事件预案 |
| 凭据主密钥丢失或误轮换 | 所有已存云端连接无法解密 | Secret 文件与数据库分开备份、启动校验、显式可恢复轮换流程；禁止只替换环境变量 |
| TMDB Key 池泄露 | 环境、日志、页面或诊断响应暴露任意 Key、局部值或可反推标识 | Secret 文件优先；普通 API 不返回数量，管理页只返回计数、状态、并发和修订；日志/数据库/备份/任务快照禁止写入 Key |
| Key 数直接放大并发 | 配置大量 Key 后压垮 Worker、数据库或上游 | 使用“健康 Key 数 × 单 Key 并发”，再受部署全局上限和 Worker 槽位约束；不同任务公平排队 |
| 单 Key 限流拖停整个池 | 一个 Key 收到限流后全部 TMDB 请求暂停 | 每 Key 独立在途计数、冷却和禁用；动态移出/恢复健康池，只调整后续请求容量 |
| 多 Worker 重复放大并发 | 每个副本都按 Key 数计算，实际总并发变为副本数倍 | 使用部署级共享信号量与 Key 状态；无协调组件时只运行一个 TMDB 调度器 |
| API 与 Worker TMDB 配置不一致 | API 接受 TMDB 任务但 Worker 使用不同 Key 池或容量 | compose 注入同一多 Key Secret，并比较 `tmdbKeyPoolRevision`；不一致时停止接收新 TMDB 任务 |
| 插件压缩包攻击 | 目录穿越、压缩炸弹、超量小文件或覆盖已有版本 | 流式上传、临时目录、解压前后限额、规范路径校验、同版本不可覆盖和失败清理 |
| 管理前台越权 | 普通用户导入插件或读取跨租户任务 | 服务端强制 `super_admin` RBAC、管理路由隔离、CSRF/CSP、安全 Cookie 和审计；不能只依赖前端隐藏 |
| 管理海报墙跨租户串库 | 管理员选择用户 A 后返回用户 B 的服务或条目 | 先解析目标用户到 `tenantId`，再联合资源 ID 查询；缓存、搜索和 SSE 同样保留租户作用域 |
| 管理接口泄露播放能力 | 页面虽无播放按钮，但响应包含 `playbackLocator`、临时 URL 或网盘 Headers | 使用独立只读 DTO、响应字段允许列表和浏览器网络响应手工检查，禁止复用客户端文件接口 DTO |
| 管理 SSE 负载过高 | 全实例任务事件让页面和服务端连接持续高负载 | 强制用户/服务/任务过滤、聚合节流、事件游标和断线续传，列表不推送逐文件敏感路径 |
| 用户或服务误删除 | 管理员误操作导致整个媒体库不可恢复 | 软停用优先、影响范围预览、二次确认、异步删除任务、审计和明确的数据保留窗口 |
| 插件配置 Secret 泄露 | 页面回显、日志或任务快照保存插件密钥 | schema 标记 Secret、加密存储、只返回配置状态、任务引用配置修订、日志不记录值 |
| 插件配置运行中漂移 | 管理员保存新配置导致正在运行的任务行为改变 | 不可变 `configurationRevision`，运行中任务固定旧修订，新任务使用新修订 |
| SQLite 多副本并发 | 多个 API/Worker 容器共享一个文件导致锁冲突或损坏 | SQLite 只允许本机持久卷和单实例/受控写入；需要水平扩容时切换 PostgreSQL 或 MySQL |
| 三数据库行为不一致 | JSON、时间、全文搜索、分页、排序和索引结果不同 | 存储方言适配、UTC、显式排序字段、共享契约和逐后端手工验收 |
| 数据库切换丢数据 | 修改环境变量后误以为旧 SQLite 数据会自动进入新数据库 | 启动日志和管理页明确当前类型；切换不自动迁移，使用停写的专用迁移/导入流程 |
| 数据库 URL 泄露 | 日志和管理页暴露主机、用户名或密码 | Secret 文件优先，日志脱敏，状态接口只返回类型、连接状态和 schema 版本 |
| 并发执行迁移 | 多副本启动时重复升级 schema | 数据库级迁移锁、版本门禁，其他进程等待迁移完成 |
| 插件越权 | 访问未声明主机、密钥或未授权数据 | 声明式宿主、Manifest 主机审核、敏感字段隔离和限额；目标网段不做限制 |
| 元数据源不稳定 | 字段、图片地址或限额变化导致匹配与展示异常 | 版本化 Provider、字段能力、缓存失效、限频和降级状态 |
| FlyCloudHelper 强依赖 FlymbyServer | FlymbyServer 维护或网络中断时音乐扫描整体失败 | 迁移领域算法和来源适配器到 Scanner Worker；现有 FlymbyServer API 只作为参考，不作为默认上游 |
| 音乐候选误匹配 | 相似歌曲名、翻唱或同名艺人导致错误覆盖标签 | 综合标题、艺术家、专辑、时长、轨号和外部 ID；设置采用/拒绝双阈值并保留人工确认状态 |
| 音乐来源局部失效 | 单一平台协议或风控变化导致整批音乐任务失败 | 来源隔离、独立超时/熔断、`sourceWarnings`、`fast/complete` 聚合和能力降级 |
| 声纹任务占用网盘带宽和磁盘 | 对所有曲目下载完整文件导致扫描慢、临时盘耗尽 | 声纹仅作后备，限制单文件大小、并发、临时目录和 TTL，任务终态强制清理 |
| 声纹或 Key 泄露 | 调试日志、数据库或导出中保留敏感材料 | 只向 AcoustID 提交声纹和时长；Key 使用环境变量/Secret，音频、声纹和 Key 禁止持久化与记录 |
| Android TV 无网盘适配 | 可看海报墙但不能播放 | 将本地授权和 Provider 播放解析作为 TV 接入前置 |
| 关闭云端模式 | APP 本地无全量目录时海报墙为空 | 关闭前提示，云端服务不自动删除，允许重新开启后登录并选择原服务或导入离线快照 |

## 7. 建议实施顺序

1. 先落实无凭证 `/setup` 首次设置与 `setup_required` 门禁、用户名和密码至少 4 个字符、公开注册固定 `user`、`super_admin` 服务端 RBAC、会话规则、`tenantId + serviceId + libraryId` 归属链、客户端绑定和数据库唯一约束。
2. 冻结技术栈、三数据库方言/迁移框架、跨库数据迁移边界及安全与运营合规边界。
3. 冻结注册开放策略、用户名/密码最大长度与附加复杂度、首次设置完成前的网络开放流程、凭据主密钥、TMDB 多 Key/单 Key并发/部署上限、音乐环境变量与匹配阈值、管理任务控制动作、Web 海报墙无播放 DTO、插件包/配置格式和管理 API，再编写 OpenAPI、Provider SDK、媒体 Processor、目录和播放定位契约。
4. 搭建账号认证、云端服务和配置修订、默认 SQLite、PostgreSQL/MySQL 适配、长期凭据安全、TMDB Key 池调度和配置加载。
5. 完成 Web 登录/注册、个人控制台、超级管理员后台、任务 SSE、只读海报墙、审计和声明式插件导入/配置闭环，确认不可直接播放且不可导入任意代码。
6. 以 WebDAV 完成视频、音乐、有声书三个最小闭环，分别验证 NFO/TMDB 多 Key 动态并发、音频标签加 FlymbyServer 参考聚合链路、章节/分卷；声纹后备单独作为可选能力验收。
7. 在不修改扫描核心和目录主模型的前提下扩展光鸭、阿里云盘和百度网盘。
8. 接入 HarmonyOS 云端模式的注册登录、选择/创建服务与目录，保持本地播放链路。
9. 在 API 稳定后接入 Android TV 网盘、账号登录、服务选择和云端目录。
10. 完成备份、安全、合规和部署交付。

## 8. 自验收清单

按用户项目规则不创建自动化测试。实现阶段保留以下手工和静态验证：

1. OpenAPI 语法和 DTO 生成静态检查。
2. 数据库迁移文件顺序和回滚路径检查。
3. Docker 镜像构建、API/Worker 启动、健康检查和持久卷检查。
4. 首批 Provider 的真实账号连接和路径枚举由用户验证；后续适配器使用同一能力清单验收。
5. 视频、音乐、有声书分别验证识别、元数据、层级关系、排序和文件定位。
6. 扫描失败、云端凭据过期、重新授权、暂停恢复和删除保护由用户验证。
7. HarmonyOS 和 Android TV 真机页面、焦点、SSE 断线重连和直接播放由用户验证。
8. 数据库业务表、目录导出、日志和崩溃信息中不得出现账号明文密码或网盘明文凭据；凭据表只能出现不可读密文。
9. 使用两个用户名密码账号创建相同 Provider、账号和路径的服务，验证媒体库、任务、SSE、缓存和导出完全隔离。
10. 使用同一账号创建两个配置相同的云端服务，验证不同 `serviceId` 对应不同媒体库，不按名称、账号或路径合并。
11. 在两台设备登录同一账号并选择同一 `serviceId`，验证即使本地 `clientServiceId` 不同仍读取同一 `libraryId`；未完成本地网盘授权的设备只能浏览不能播放。
12. 伪造其他租户的 `libraryId`、`jobId` 和 `exportId` 时，所有入口均拒绝访问。
13. 分别在管理端保存重复多 Key、整组替换和清空 Key 池，核对去重后 Key 数、配置修订、Provider 状态、即时动态并发、审计记录和敏感值不回显。
14. 分别验证 APP 和 Web 的已有账户登录、新建账户、令牌刷新/退出；确认 `/login` 与 `/register` 可相互跳转，`user` 进入 `/app`，`super_admin` 可访问 `/admin` 和管理 API。
15. 手工导入合法插件、同版本插件、脚本包、目录穿越包和超限压缩包，确认预检、拒绝、失败清理及旧版本不被覆盖。
16. 插件升级时保留运行中任务的固定版本，停用只影响新任务，被引用版本不能物理删除。
17. 不设置数据库变量启动并验证默认 SQLite 文件、持久卷、WAL、外键和重启后数据保留。
18. 分别使用 PostgreSQL 和 MySQL 环境变量启动，核对迁移版本、租户唯一约束、任务写入和三类媒体查询结果。
19. 验证非法数据库类型、缺少连接地址、不可写 SQLite/密钥目录、主密钥指纹不一致和 API/Worker 配置不一致时拒绝提供服务且不输出密码或密钥。
20. 不配置主密钥启动全新实例，确认自动生成持久化文件、设置管理员后支持复制/下载、确认前可恢复读取、确认后不再返回原文；删除密钥后对已有数据库启动必须失败。
21. 修改数据库类型时确认不会自动迁移旧管理员、用户、服务、任务、目录和插件数据，独立持久卷主密钥仍保留；如首期提供迁移命令，由用户按停写、迁移、校验、切换和回滚流程验证。
22. 分别验证音乐 `auto + fast`、`auto + complete` 和指定单一来源；单个来源失败不能让其他来源候选丢失。
23. 使用同名曲目、不同艺术家、不同专辑和时长偏差数据，验证自动采用阈值、`needs_review` 和拒绝状态不会错误覆盖本地标签。
24. 未安装 `fpcalc`、未配置 AcoustID Key、声纹文件超限和正常声纹识别分别验证；文字检索始终可用，临时音频在全部终态均被删除。
25. 停止 FlymbyServer 或阻断其接口后执行音乐扫描，验证 FlyCloudHelper 的内置音乐链路没有默认在线依赖。
26. 使用多个用户和多个服务验证管理列表、详情、任务 SSE、海报墙、搜索索引和缓存不会串库。
27. 检查管理海报墙页面和浏览器网络响应，确认不存在播放器、播放按钮、媒体预览、`playbackLocator`、临时 URL、网盘 Headers 或凭据引用。
28. 停用用户、停用服务和删除单个服务，确认作用范围、二次确认、异步结果、审计日志以及其他用户/服务不受影响。
29. 导入含 `configurationSchema` 的插件，验证普通字段、Secret 掩码、连接校验、配置修订和运行中任务固定旧修订。
30. 管理任务页在扫描/识别/刮削/落库各阶段验证实时计数、断线续传、筛选和脱敏错误。
31. 分别从 APP 和管理前台创建云端服务，验证连接 Secret 只写不读、扫描/刮削配置生成修订、触发扫描只提交 `serviceId` 和幂等参数。
32. 选择已有服务时验证 APP 当前连接和路径不会覆盖云端配置；选择“创建新服务”时验证生成新的 `serviceId + libraryId`。
33. 分别以 1、2、4 个唯一健康 TMDB Key 验证有效并发按公式变化；空项和重复项不得增加并发。
34. 手工模拟单 Key 限流、认证失败、网络错误和恢复，验证只影响对应 Key，健康数量和有效并发实时调整且不会无限重试。
35. 启动多个 Worker 验证部署总在途请求不超过 `FLYCLOUDHELPER_TMDB_MAX_CONCURRENCY`；API/Worker 池修订不一致时拒绝新 TMDB 任务。
36. 在注册、超级管理员创建用户、初始化超级管理员和密码重置分别输入 3 个及恰好 4 个字符的用户名/密码，确认 3 个被统一拒绝、4 个通过长度校验；登录失败仍只返回通用错误。
37. 修改公开注册请求提交 `role=super_admin`，确认请求被拒绝且不创建账号；普通用户直接访问 `/admin` 和管理 API 返回 `403`。
38. 授予和撤销 `super_admin` 时验证最近重新认证、二次确认、旧会话撤销和审计；尝试降级、停用或删除最后一个有效超级管理员必须失败。
39. 使用空数据库启动时确认所有 Web 入口进入 `/setup`，账号步骤不出现初始化凭证字段，只要求超级管理员用户名、密码和确认密码；初始化完成前注册、登录和全部业务 API 不可用。
40. 并发提交两次不同的首次设置，确认只有一个事务创建 `super_admin`；自动生成密钥时先完成备份确认再进入 `/admin`，再次提交返回初始化已完成。

## 9. 不在首期计划内

| 项 | 原因 |
| --- | --- |
| 视频或音频代理和转码 | 违反直接播放边界，并显著提高性能、带宽和运维成本 |
| 公开分享和跨用户搜索 | 超出用户私有媒体目录定位，且权限与隔离模型尚未定义 |
| 任意代码插件 | 无法控制代码执行、网络访问和凭据泄露风险 |
| 向客户端同步服务端网盘凭据 | 云端凭据仅供 Scanner Worker 使用；各端播放授权保留在本地安全存储，服务端不得下发 |
