## 2. 总体结论

原方案的任务、目录和客户端播放边界可复用，但“APP 每次上送临时凭据并通过 `clientServiceId` 解析媒体库”的身份与配置链不再适用。本次改为单一用户名密码认证，用户名和密码均至少 4 个字符，角色固定为 `user` 和 `super_admin`。服务端生成 `serviceId + libraryId`，APP 登录后选择已有服务或创建新服务，服务端长期加密保存连接并版本化扫描/刮削配置，后续扫描只引用 `serviceId`。Web 新增 `/login`、`/register`、`/app` 和 `/admin`：公开注册固定创建 `user`，普通用户只管理本人数据，`super_admin` 可以跨用户管理用户、服务、插件、任务和配置。TMDB 同时从单 Key 草案改为部署级多 Key 池，实际并发随健康 Key 数动态变化，并由部署总上限、多 Worker 共享信号量和任务公平队列约束。FlymbyServer 仍只提供音乐代码依据，不作为默认在线依赖。所有 FlymbyScanner 接口仍属于“方案已定义、服务端尚未实现”。

## 3. 关键不一致清单

| 编号 | 不一致点 | 需求依据 | 接口/代码依据 | 影响 | 建议 |
| --- | --- | --- | --- | --- | --- |
| G-01 | 当前没有云端服务探测接口 | 开启云端模式时校验 Scanner 可用性 | 当前四个添加页只验证网盘本身 | 不能安全进入账号步骤 | 新增 `/api/v1/system/info` |
| G-02 | 当前没有服务托管型扫描 API | APP 或管理前台按云端服务触发扫描 | `WebDavScanService` 在 APP 进程内运行 | 不能移出本地数据，且每次提交配置会产生漂移 | 新增云端服务配置修订和 `/services/{serviceId}/scan-jobs` |
| G-03 | 首页、列表和搜索直接读本地库 | APP 不保存大量目录数据 | `WebDavVideoHome`、聚合搜索和 FlyHub Provider | 即使远端扫描，APP 也无法展示 | 建立目录 Repository 和查询 API |
| G-04 | 详情页依赖本地子项/文件关联 | 远端内容需实时播放 | 视频详情当前查询本地剧集表，音乐/有声书各有独立模型 | 详情可见但无法统一选集、选曲或选章 | 新增 children/files 接口与 `playbackLocator` |
| G-05 | Android TV 没有网盘类型 | 远端服务可供 TV 使用 | `MediaServiceType` 无四种网盘 | TV 无法保存凭据或解析播放地址 | 新增 TV 网盘 Provider，不仅是调目录 API |
| G-06 | 目录备份契约未冻结 | 扫描后可生成 APP 可用备份 | 现有 APP 有本地快照，但新服务没有格式 | 导出后可能无法导入 | 先确认新格式或兼容层 |
| G-07 | 用户名密码认证、4 字符校验和租户上下文尚未实现 | 一个实例服务多个用户，统一使用用户名和密码且二者都至少 4 个字符 | 当前没有注册、登录、刷新和退出实现 | 无法安全列出用户服务，客户端可能伪造归属，各端校验可能不一致 | 新增 `/auth/register`、`/auth/login`、`/auth/refresh`、`/auth/logout`、统一长度校验、Argon2id 和会话轮换；`tenantId` 只从认证上下文取得 |
| G-08 | 原目录模型只有影片和剧集 | 服务还要扫描音乐和有声书 | `video_item`、`video_episode`、episodes API | 音乐/有声书会被迫套用视频结构 | 改为通用条目、类型扩展和 children 关系 |
| G-09 | 当前网盘类型是封闭联合类型 | 后续网盘会继续增加 | `CloudDriveProviderType` 固定四种值 | 每次扩展都可能改协议和核心代码 | 服务端使用开放 ID、能力协商和适配器注册 |
| G-10 | 元数据配置只有 TMDB/视频插件 | 音乐和有声书也需要识别和刮削 | `video_metadata` 与 TMDB 配置 | 无法表达标签、音乐源和书籍源 | 改为按 `mediaType` 的 metadata profiles |
| G-11 | 云端服务没有服务端规范身份 | 服务可由 APP 或管理前台创建，并由多个设备选择 | 当前只有 APP `ServerInfoData.serverId` | Web 创建的服务无 APP ID，新设备也不应复制旧设备 ID | 服务端生成 `serviceId + libraryId`；`clientServiceId` 只放入设备绑定表，多端通过账号服务列表选择 |
| G-12 | 服务端没有 TMDB 多 Key 池和动态并发 | TMDB 可配置多个 Key，并按 Key 数量动态修改刮削并发 | 当前只有 `builtin.tmdb` 标识和旧单 Key 草案 | Worker 无法利用多 Key，或多副本无上限放大并发 | 新增复数环境变量/Secret、Key 状态池、动态公式、部署级信号量和脱敏管理状态 |
| G-13 | 没有首次设置、Web 登录/注册、个人控制台、超级管理员后台和插件导入接口 | 服务需要首次设置首个管理员、普通用户入口与 `super_admin` 全局管理入口 | 当前仅有声明式插件概念 | 服务无法安全初始化，用户不能自行管理服务，超级管理员无法安装和管理刮削源 | 新增 `/setup`、`/login`、`/register`、`/app`、`/admin`、个人/管理 API、插件持久卷和安全预检流程 |
| G-14 | 数据库后端尚无实现 | 默认 SQLite，也可配置 PostgreSQL/MySQL | FlymbyScanner 当前只有方案文档，没有配置加载、连接器或迁移代码 | Docker 默认行为、迁移和扩容路径尚未落地 | 按已确认变量实现数据库类型、连接地址/Secret、SQLite 路径和切换不自动迁移的规则 |
| G-15 | 音乐 Processor 尚无来源聚合与匹配契约 | 音乐刮削可参考 FlymbyServer 已有方法 | FlymbyServer 已有多来源、`fast/complete`、统一候选和 Chromaprint/AcoustID；FlymbyScanner 此前只有泛化占位描述 | 容易重复设计、错误强依赖线上接口或对全部曲目执行高成本声纹 | 迁移领域方法到 Worker，冻结 Provider 注册表、候选字段、阈值与后备触发条件 |
| G-16 | 管理前台缺少用户/服务创建和扫描触发契约 | 前端需要创建用户和云端服务并进行扫描刮削 | 原方案只有已有用户/服务查看和状态管理 | 管理员无法完成独立闭环 | 新增用户创建/密码重置、服务创建/连接验证/配置修订和扫描触发接口 |
| G-17 | 管理任务接口只有分页摘要 | 前端需要展示扫描刮削实时进度 | 普通客户端有单任务 SSE，管理 API 只有 `/admin/jobs` 列表 | 管理员不能按用户和服务实时查看跨租户任务 | 新增管理任务详情和带过滤、游标续传的管理 SSE |
| G-18 | 管理前台没有海报墙接口和页面 | 前端需要海报墙展示已扫描刮削内容 | 当前只有租户目录 API，返回模型包含客户端播放相关能力 | 直接复用会缺少跨租户筛选并可能把播放定位暴露给浏览器 | 新增管理端海报墙/详情/子项只读 DTO 和接口，明确删除播放字段 |
| G-19 | 插件管理没有配置模型 | 前端需要配置插件 | 现有方案只有导入、预检、启停、版本和删除 | 插件参数及 Secret 无法安全维护，任务可能随配置修改漂移 | Manifest 增加受限 `configurationSchema`，保存不可变 `configurationRevision` |
| G-20 | APP 缺少登录/注册和服务选择分步页面 | 开启云端模式后输入地址、账号密码，再选择或创建服务 | 当前添加页只处理网盘自身连接 | 无法区分选择已有服务与创建新服务，容易误覆盖配置 | 增加“服务检测 → 登录/注册 → 服务选择/创建”三步流程 |
| G-21 | 服务端没有长期凭据库 | 后续扫描不再由 APP 上送连接 | 原方案仅设计任务临时凭据和 TTL | APP 离线后无法扫描，凭据过期也无法统一维护 | 新增每服务长期密文、主密钥 Secret、修订和 `reauthorization_required` 状态 |
| G-22 | 任务接口仍接受完整连接与配置 | 扫描配置由云端服务持久管理 | 原请求包含 Provider connection、roots 和 metadata profiles | 历史不可审计，容易泄密和多端竞争覆盖 | 扫描请求只带幂等参数，服务端冻结当前配置修订 |
| G-23 | 登录云端账号不等于具备本地播放授权 | 服务端凭据不得下发，播放仍由 APP 发起 | 新设备可能只有云端账号，没有本地网盘 Token | 能浏览但无法播放，或错误要求服务端返回 Secret | 目录允许只读；播放前检查本地 Provider 授权并引导完成授权 |
| G-24 | Key 数量与并发不是简单无上限相乘 | 用户要求根据 Key 数动态并发 | 还需受 Worker、数据库、上游和多副本约束 | 配置大量 Key 可能压垮整个服务 | 使用 `min(全局上限, 健康 Key 数 × 单 Key 并发, Worker 可用槽位)`，并做任务公平调度 |
| G-25 | 当前没有 `user/super_admin` 角色与服务端 RBAC | 普通用户只管理本人，超级管理员管理全局 | 原方案只笼统描述管理员权限 | 普通用户可能通过构造管理请求读取或修改跨租户数据 | 认证上下文返回角色；所有 `/api/v1/admin/*` 强制校验 `super_admin`，普通用户返回 `403` |
| G-26 | 公开注册缺少角色防提权规则 | 注册入口只能创建普通用户 | 若 DTO 直接接收 `role`，可篡改请求注册为超级管理员 | 实例被完全接管 | 注册接口拒绝 `role` 并固定创建 `user`；`super_admin` 仅初始化或由现有超级管理员授予 |
| G-27 | 超级管理员生命周期保护未定义 | 服务必须始终保留可管理入口 | 任意停用、删除或降级可能移除最后一个超级管理员 | 无法进入后台恢复系统 | 角色变更要求最近重新认证、二次确认、撤销旧会话和审计；禁止处理最后一个有效 `super_admin` |
| G-28 | 首次设置状态与一次性写入接口尚未实现 | 首次使用时现场设置超级管理员账号密码，不需要初始化凭证 | 当前没有 `setup_required` 状态、初始化页面或事务锁 | 未初始化实例无法使用，或并发请求同时争抢首个超级管理员 | 新增 `/setup`、`GET /api/v1/setup/status` 和 `POST /api/v1/setup/super-admin`；初始化前关闭其他业务接口，事务只允许一次成功，部署者先初始化再开放公网 |

## 7. 不一致项详情

### 7.1 云端服务可用性不能只判断 HTTP 200

需求要求在添加网盘服务时确认远端可用性。若只请求根地址并判断 200，反向代理默认页、登录页或其他服务都可能被误认为 FlymbyScanner。因此 `/api/v1/system/info` 必须返回固定服务名、稳定实例 ID、协议版本、状态和 Provider 能力。

### 7.2 远端查询不应直接复制本地 SQL 接口

`WebdavLocalStore` 的查询方法是为本地 SQLite 和视频页面定义的。服务端应按“首页、facets、列表、详情、children、文件、搜索、变更”设计通用 API，再由 HarmonyOS 的 `MediaCatalogRepository` 分别转换为视频、音乐和有声书页面模型。

### 7.3 Android TV 不能只接入目录查询

Android TV 可以在没有网盘凭据时浏览目录，但不能播放。要完成可用接入，必须同时增加网盘授权、本地凭据安全存储、`playbackLocator` 解析和最终 URI/Headers 构造。现有 mpv/Media3 的 `PlaybackRequest` 可用于视频；音乐队列、单曲切换和有声书章节/进度仍需独立音频领域接入。FlymbyScanner 不代理媒体流。

### 7.4 备份不再是多端同步主通道

云端模式下，日常多端同步由查询 API、SSE 和 `catalogVersion` 完成。备份只用于云端绑定迁移或离线全量恢复，不应再要求每次扫描后下载快照才能使用。

### 7.5 Provider 与媒体类型必须分别扩展

网盘 Provider 解决“如何枚举和定位文件”，媒体 Processor 解决“如何识别和组织内容”，二者是正交维度。不能为每个“网盘 × 媒体类型”组合复制扫描服务；通用扫描器应先得到统一 `source_file`，再按媒体类型路由。

### 7.6 服务归属不能使用名称、地址或网盘账号推断

`serviceInstanceId` 只识别 FlymbyScanner 部署，不能区分同一部署中的用户和网盘服务；`libraryId` 是目录资源 ID，也不能单独代表授权。正确契约是服务端从用户名密码登录态得到 `userId + tenantId`，创建云端服务时生成规范 `serviceId + libraryId`。多设备登录同一账号后从服务列表选择同一 `serviceId`；APP 已有 `serverId` 只映射为当前设备的 `clientServiceId` 绑定别名。显示名称、连接地址、Provider 账号、Token、扫描路径和根目录只能作为配置，不能参与归属判断。

服务列表、创建和绑定接口必须具有以下语义：

1. `GET /api/v1/services` 只返回认证账号有权访问的服务，可按当前 `providerType` 筛选，不接收用于授权的 `tenantId`。
2. `POST /api/v1/services` 验证连接后由服务端生成 `serviceId + libraryId`，并事务保存加密凭据和首个扫描/刮削配置修订。
3. `POST /api/v1/services/{serviceId}/client-bindings` 只建立 `clientDeviceId + clientServiceId -> serviceId`，不得覆盖服务连接和配置；Provider 类型变化时返回 `409`。
4. 扫描任务只提交 `serviceId` 路径参数、请求幂等信息和扫描模式，服务端校验所有权并冻结当前配置修订。
5. 所有后续查询、SSE、缓存、搜索索引、对象存储和导出都必须带 `tenantId + serviceId + libraryId` 服务端作用域。
6. 跨账号恢复备份时必须登录目标账号并显式选择或创建服务，不能直接接管原媒体库。

### 7.7 TMDB 使用单一来源的多 Key 池和部署级动态并发

TMDB Key 池属于 FlymbyScanner 部署级敏感配置，不属于 APP、租户、媒体库或扫描任务。API 和 Worker 统一读取 `FLYMBYSCANNER_TMDB_API_KEYS`，或优先读取 `FLYMBYSCANNER_TMDB_API_KEYS_FILE` 的逐行 Key；两个来源不合并，数据库和管理页面也不提供另一套可编辑 Key 配置。

配置数量不能直接作为无上限并发。服务只统计唯一非空且当前健康的 Key，并使用 `min(TMDB_MAX_CONCURRENCY, healthyKeyCount × TMDB_CONCURRENCY_PER_KEY, workerAvailableSlots)` 计算实际并发。调度器选择在途请求最少的健康 Key，在并列时轮询；某个 Key 被限流时独立冷却，认证失败时独立禁用，其他 Key 继续工作。多 Worker 必须共享部署级信号量和状态，否则只能运行一个 TMDB 调度器。

普通能力接口只返回 TMDB 可用状态，不暴露 Key 数量和容量。管理员配置状态接口可以返回配置/健康/冷却/禁用数量、实际并发和池修订，但 Key 原文、局部值、哈希和可反推标识不得进入响应、日志、数据库、任务快照、诊断包或备份。修改环境变量或 Secret 后重启 API/Worker 形成新修订；修订不一致时拒绝新的 TMDB 任务。

### 7.8 前台导入与配置只覆盖声明式元数据插件

插件导入和配置入口位于 `super_admin` 超级管理员后台 `/admin`。首期导入包为 `.flymby-plugin`，服务端必须在启用前完成压缩包安全、Manifest schema、协议版本、域名、HTTP 方法、媒体类型、插件版本和 SHA-256 校验。配置页面只能根据 Manifest 的受限 `configurationSchema` 生成，Secret 加密且不回显，每次保存产生不可变修订。普通 `user` 只能选择已启用插件，不能调用插件管理接口。Provider 适配器具有服务端代码执行能力，不能复用该上传和配置入口，仍通过镜像或受控挂载安装。

### 7.9 数据库默认值和切换边界必须固定

不配置 `FLYMBYSCANNER_DATABASE_TYPE` 时服务必须直接使用 SQLite，不能因为未部署 PostgreSQL/MySQL 而启动失败。选择 `postgres` 或 `mysql` 后必须提供连接地址环境变量或 Secret 文件，并保证 API、Worker、迁移器连接同一数据库和 schema 版本。环境变量切换只选择存储后端，不承担数据复制；从 SQLite 扩容到外部数据库需要单独的停写迁移或导出导入流程。管理前台只展示数据库类型、连接状态和 schema 版本。

### 7.10 参考 FlymbyServer 不等于调用 FlymbyServer 接口

FlymbyServer 已有音乐实现覆盖七种来源标识、`fast/complete` 自动聚合、统一候选字段、单来源故障隔离、MusicBrainz 串行限流，以及 `fpcalc -> Chromaprint -> AcoustID -> MusicBrainz` 的可选声纹链路。这些内容应作为 FlymbyScanner 音乐 Processor、Provider 注册表和管理能力页的代码依据。

FlymbyScanner 不应直接把现有 `/api/v1/tools/audio-scrape/search` 或 `/recognize` 当作内部必需上游：这些接口绑定 FlymbyServer 自己的访问令牌、加密信封、上传限额和限频规则，也会引入跨服务故障与租户文件信息转发。首期应迁移领域算法与适配器，在 Worker 内按云端服务冻结的音乐 Profile 修订运行；APP 只在创建或编辑云端服务时维护音乐 Profile，并查看最终目录，不直接消费候选搜索接口。

批量扫描优先使用文件名、目录名和内嵌标签执行文字检索。声纹只在低置信度、无候选或人工触发时使用，并要求服务能力、临时文件上限和清理机制全部可用。即使声纹不可用，文字检索和本地标签建库也必须继续。

### 7.11 Web 前端同时包含普通用户个人控制台和超级管理员后台

Web 前端统一由 FlymbyScanner 提供，但权限分为两层。普通 `user` 登录 `/app` 后，只能创建和维护自己的云端服务、查看自己的任务与海报墙；服务端直接使用认证上下文中的 `tenantId`，不接受用户自行选择目标租户。`super_admin` 登录 `/admin` 后可以跨用户管理，但每次查询都必须从目标 `userId` 解析真实 `tenantId`，再联合 `serviceId`、媒体库、任务和条目 ID 校验资源链。不能为了管理查询方便而删除 Repository 的租户参数，也不能把管理权限实现为跳过数据作用域。

超级管理员的用户和服务管理首期覆盖创建普通用户、重置密码、查看、角色授予/撤销、启停、会话撤销、创建/维护云端服务、触发扫描和受保护删除。角色变更需要最近重新认证、二次确认、目标旧会话撤销和审计，并禁止降级、停用或删除最后一个有效 `super_admin`。超级管理员可以提交新的网盘连接、扫描路径和刮削配置，但 Secret 保存后只显示配置状态，历史任务快照不可修改。是否开放暂停、继续和取消任务仍属于待确认项。

### 7.12 管理任务进度需要独立 SSE

普通客户端 SSE 只允许读取当前租户的单任务事件；管理页面需要按用户、服务、媒体库、媒体类型和状态筛选多个任务，因此应使用独立 `/api/v1/admin/jobs/events`。事件必须包含单调游标、任务 ID、阶段、计数、可空百分比、吞吐和脱敏错误，并支持断线续传。逐文件完整路径、网盘 URL、请求头和凭据不得进入事件。

### 7.13 海报墙无播放需要接口和页面双重限制

只隐藏播放按钮不够，因为浏览器仍可从接口响应或开发者工具取得 `playbackLocator`。管理海报墙必须使用独立只读 DTO，只包含图片、标题、媒体类型、年份、匹配状态、更新时间、类型扩展摘要、子项和文件数量。详情接口同样不得返回 `playbackLocator`、临时 URL、网盘 Headers、凭据引用或媒体预览地址。

海报墙按“用户 → 用户服务 → 媒体库 → 媒体类型”选择作用域，并支持搜索、facets、排序、游标分页和 `catalogVersion`。扫描任务每次事务提交后即可显示新条目，不需要等待整个任务完成。

### 7.14 插件配置必须版本化

插件导入解决“安装哪个版本”，插件配置解决“该版本使用哪些参数”，两者不能混为一个可变记录。Manifest 通过受限 `configurationSchema` 描述表单，Secret 加密保存并只返回是否已配置。每次保存生成新的 `configurationRevision`，任务快照固定插件版本、SHA-256 和配置修订号；运行中任务不受后续配置修改影响。

### 7.15 选择已有服务与创建新服务必须是两个明确动作

APP 添加网盘时已经持有一份本地连接和路径配置，但登录后看到的已有云端服务可能正在被其他设备使用。如果用户选择已有服务，接口只能创建客户端绑定，不能把当前本地配置隐式写入服务端；如果用户选择“将当前服务创建为新的云端服务”，才调用创建接口并一次性上传当前连接、扫描路径、媒体类型和刮削配置。后续修改云端服务必须进入独立编辑流程并产生配置修订，避免“下一步”操作造成无提示覆盖。

### 7.16 服务端扫描凭据与客户端播放授权是两套安全边界

FlymbyScanner 长期加密保存的网盘凭据只供 Scanner Worker 枚举和读取元数据，任何查询、导出、管理页面和客户端接口都不得返回。APP 或 Android TV 要播放时仍需本机 Provider 授权，再用 `playbackLocator` 解析 URI/Headers。因此新设备仅凭云端地址、用户名和密码就能找到并浏览指定媒体库，但不能自动取得播放权限。

### 7.17 登录和注册入口必须明确且共用认证契约

Web 前端必须提供 `/login` 和 `/register` 两个明确入口，登录页包含“注册新用户”，注册页包含“已有账号，去登录”。两页都可以先提示用户名和密码至少 4 个字符，但最终校验必须由服务端统一执行。注册、超级管理员创建用户、初始化超级管理员和密码重置使用相同长度规则；登录失败始终返回统一的用户名或密码错误，避免通过格式差异枚举账号。

公开注册只能产生 `user`。注册 DTO 不定义 `role`，服务端收到角色字段时拒绝请求，不能因为前端隐藏了角色控件就认为安全。登录成功后通过 `/auth/me` 或安全会话得到服务端角色：`user` 进入 `/app`，`super_admin` 进入 `/admin` 或原站内授权目标。

### 7.18 超级管理员权限必须在服务端强制执行

所有 `/api/v1/admin/*` 接口都必须检查当前有效会话的 `super_admin` 角色，普通 `user` 直接访问返回 `403`。前端菜单和路由守卫只负责用户体验，不能成为授权边界。超级管理员可以管理全部用户、服务、任务、海报墙、插件和配置，但仍不得查看网盘凭据明文、TMDB Key 原文或播放定位，也不能取消 Repository 的租户作用域。

首个 `super_admin` 通过部署初始化流程产生；后续只能由现有超级管理员通过受保护接口授予。授予、撤销、停用和删除均需检查操作后至少保留一个有效超级管理员，并将操作人、目标用户、前后角色、结果和时间写入不含敏感值的审计日志。

### 7.19 首个超级管理员必须在首次使用页面设置

空数据库实例启动后进入 `setup_required`，Web 根路径及登录、注册、个人控制台和超级管理员后台都转到 `/setup`。页面只提供超级管理员用户名、密码、确认密码和“完成设置”按钮，用户名与密码均至少 4 个字符，不显示也不校验一次性初始化凭证，账号密码不从环境变量读取。

`POST /api/v1/setup/super-admin` 必须在数据库事务和初始化锁内同时确认 `initialSetupCompleted=false` 且不存在任何 `super_admin`，原子创建账号、写入 `initialSetupCompletedAt` 并建立安全会话；两个并发请求只能有一个成功。初始化完成后 `/setup` 永久关闭，即使管理员数据被异常删除也不能自动重开，后续超级管理员只允许由已有超级管理员授予。由于首次设置不要求额外凭证，实例初始化前不得直接暴露到公网；部署说明必须要求部署者先在受控网络完成设置，再开启反向代理、防火墙放行或公网端口映射。

## 9. 下一步建议

1. 先落实无需初始化凭证的 `/setup`、`setup_required` 门禁、初始化事务锁、用户名和密码至少 4 个字符、公开注册固定 `user`、`super_admin` 服务端 RBAC、登录/注册/令牌、`userId + tenantId + serviceId + libraryId` 身份链、客户端绑定和数据库唯一约束。
2. 确认技术栈、凭据主密钥、TMDB 单 Key/部署级并发默认值与多 Worker 协调方式、三数据库方言/迁移框架、跨库迁移工具边界、首次设置前的网络开放流程和 APP 本地绑定迁移版本。
3. 冻结 Web“首次设置 → 登录 ↔ 注册 → 按角色进入 `/app`/`/admin`”、APP“检测 → 登录/注册 → 选择/创建服务”交互、TMDB Key 池状态与管理 DTO、音乐默认来源、匹配阈值、管理任务动作、管理 SSE、海报墙无播放 DTO、插件 `configurationSchema`/修订和图片策略，并写入 OpenAPI。
4. 先实现首次设置、账号认证、RBAC、Web 登录/注册和个人控制台、云端服务及配置修订、长期加密凭据、TMDB Key 池/动态并发、默认 SQLite、PostgreSQL/MySQL 方言、统一配置加载，以及超级管理员后台用户/服务/任务/海报墙/插件配置安全闭环。
5. 分别验证三种数据库的租户约束、任务事务、排序、搜索和目录版本语义，再允许进入客户端联调。
6. 以 WebDAV 分别完成视频、音乐和有声书最小端到端闭环；音乐同时验证 FlymbyServer 参考聚合链路、单来源降级和可选声纹后备，确认通用模型没有视频耦合且租户隔离完整。
7. 在目录契约稳定后接入 Android TV，避免两端分别发明字段。
8. 备份、跨库迁移、媒体库转移和用户数据同步按确认范围分阶段进入。
